## 功能概述

渐进阅读模块管理 Topic（主题）与 Extract（摘录）的阅读节奏，提供**独立于 SRS 复习**的调度与会话。当前产品形态为**统一工作区**（资料库 + 专注阅读一体）：

- 一键「开始学习」入口；队列长度由每日上限决定（无时间盒）
- **跨会话日额度**：设置「每日渐进阅读上限」按今日已完成的**阅读**条目数扣减（`completedCount − reviewProcessed`），重开会话不会无限续杯；`0` 仍表示不限制
- 可随时中断的阅读断点恢复
- 键盘主路径（下一篇 / 摘录 / 挖空 / 重要性）；主栏另有完成与 ⋯ 更多（Extract 更多内：问答 / 方向）
- Topic → Extract → Item（Cloze / Q&A / Direction）漏斗（挖空与问答/方向默认可 `keep_extract` 多次制卡；离开靠下一篇 / 完成 / 推后）；摘录成功提示大约几天后回流
- 可选混合学习（阅读队列中混入到期 SRS 复习卡）
- 资料库显式「一键溢出推后」、漏斗诊断、资料库三级来源树（会话启动本身不自动改 due）

## 右键加入渐进阅读

对**普通、非查询块**的块把手右键菜单提供 Topic 入口（第一版仅单块，不支持多选批量、不做网页导入/剪藏）：

| 块状态 | 菜单项 | 行为 |
| --- | --- | --- |
| 非 Topic（无 `#card` 或 `type` 不是 `topic`） | **加入渐进阅读** | 调用 `createTopicCardByBlockId`：写入 `#card type=topic`，再 `ensureIRState` + 索引；**默认优先级 `DEFAULT_IR_PRIORITY = 50`**，走正常分散初始化排期，**不**自动把 `due` 改成今天 |
| 已是 Topic IR（`extractCardType(block) === "topic"`） | **今天阅读** | 仅调用 `advanceDueToToday(blockId)`，只改 `ir.due` 为本地日 00:00；不改 `ir.priority`、`readCount`、`stage` 等长期状态 |
| 查询块 | （无上述两项） | 不显示 |

实现要点：

- 菜单注册：`src/srs/registry/contextMenuRegistry.tsx`（`joinTopicIR` / `readTopicToday`），`unregisterContextMenu` 经 `registeredMenuIds` 自动覆盖
- 分类：`classifyTopicIRBlockMenu`（`src/srs/topicIRMenu.ts`）——Topic 判断优先 `extractCardType`，不是任意 `#card`
- 创建：`createTopicCardByBlockId`（`src/srs/topicCardCreator.ts`）；斜杠命令 `createTopicCard(cursor)` 验证光标后委托同一入口
- 标签写入使用 `null` cursor + `blockId`（与 Book IR 章节初始化一致）；`ensureIRState` 前 `invalidateIrBlockCache`，避免旧 type 被按 basic 初始化
- 成功/失败均有渐进阅读标题的 `orca.notify`；失败额外 `console.error`；菜单侧有 working + inflight 防双击并发

书籍相关右键（建书 / 整本移出）见 Book IR 文档。

## 自动标签开关

自动标签功能用于在 Topic 下创建子块时，自动补齐 `#card` 标签并设置 `type=extracts`。当前默认关闭，可在命令面板中手动切换：

- 命令：`SRS: 切换渐进阅读自动标签`（`{plugin}.toggleAutoExtractMark`）
- 启用时：新建子块会自动打标签并初始化 Extract
- 关闭时：新建子块不做自动标记

说明：默认值由插件设置项 `enableAutoExtractMark` 控制；也可在统一工作区「设置」抽屉中修改（与插件 Settings 面板同步）。

**watcher 生命周期加固（2026-07-26，`incrementalReadingAutoMark.ts`）**：

- `startAutoMarkExtract` 有**重入守卫**：已在运行时重复 start 为幂等 no-op（日志「已在运行，跳过重复启动」），不会覆盖旧订阅句柄造成 valtio 订阅泄漏（对齐 `recentDeckManager` 先例）
- 500ms 防抖定时器提升为**模块级句柄**，`stopAutoMarkExtract` 时 `clearTimeout`，杜绝 stop 后残留回调再触发扫描
- **世代计数**（`watcherGeneration`）：扫描/写入路径逐步校验世代，stop 后在途异步一律中止——stop 之后**零扫描、零写入**
- 回归：`incrementalReadingAutoMark` 相关测试（5 用例）

## 数据模型

渐进阅读状态存储在 Block Properties 中，字段如下：

- `ir.priority`：重要性（存储字段名不变），0-100（默认 50，数值越大越重要/越优先出现）
- `ir.lastRead`：上次阅读时间（Date 或 null）
- `ir.readCount`：累计阅读次数
- `ir.due`：下次到期时间（Date）
- `ir.intervalDays`：当前间隔（天，可为小数），用于计算下一次 `ir.due`
- `ir.postponeCount`：累计推后次数（手动推后 + 溢出/自动推后）
- `ir.stage`：漏斗阶段（由真实动作推进，见下表）
- `ir.lastAction`：最近一次动作（如 `next` / `postpone` / `autoPostpone` / `priority` / `extract` / `itemize`）
- `ir.position`：Topic 队列位置（数值越小越靠前）
- `ir.resumeBlockId`：继续阅读进度（下次打开卡片时跳转到该 blockId）
- `ir.breakpoint`：JSON 阅读断点（`previewBlockId` / `selection` / `updatedAt` / `schemaVersion` / `viewportAnchor`）；v2 含视口偏移对齐；通道 version 合并逻辑在 `irBreakpointStorage.ts`（与 schemaVersion 无关）
- `ir.autoPostponeBatchId`：自动推后批次 ID（撤销时与 `lastAction=autoPostpone` 一起校验；持久化字段）
- `ir.sourceTopicId`：Extract 来源 Topic（**创建摘录时必须写入**；章节完成 strip 后仍保留在 Extract 上，资料库靠此挂回结构）
- `ir.sourceBookId` / `ir.sourceBookTitle`：书籍来源元数据
  - **章节 Topic 初始化**时写入（Book IR / 批量 init）
  - **Extract 创建**时：若来源 Topic 是书章节（带 `ir.sourceBookId`），同步写入 Extract 的 `ir.sourceBookId` / `ir.sourceBookTitle`（耐久溯源，不依赖章节仍为 live Topic）
  - **收集器 legacy**：若 Extract 仅有 `sourceTopicId`、书籍字段缺失，可在内存中从**仍 live** 的父 Topic 继承 book meta；章节已完成后该路径不可用，故创建路径必须写耐久属性
- `ir.batchId` / `ir.batchCreatedAt`：书籍批量初始化批次元数据（可选）
- Item 来源追溯（转化成功后写在 Item 上）：`ir.sourceExtractId`、`ir.sourceTopicId`、`ir.sourceTextSnippet`、书籍字段

类型定义：`src/srs/incremental-reading/irTypes.ts`（含 `IRStage`、`IRLastAction`、`IRReadingBreakpoint`、`IRCollectResult` 等）。`lastProcessedAt` / 顶层 `breakpointVersion` 在类型中预留，断点版本以 `ir.breakpoint` 内 `version` 与合并逻辑为准。

标签属性补充：

- `#card.priority`：数字优先级（Number）
  - 仅用于 Orca 的标签属性面板展示/筛选
  - 插件会在写入 `ir.priority` 后主动同步该值到 `#card.priority`
  - 调度/选卡逻辑只使用 `ir.priority`，不会读取 `#card.priority`

## 调度算法

优先级调度采用单一真相：**只使用 `ir.priority(0-100)`**，并引入“间隔增长”避免材料长期高频出现。

更多“排期 vs 今日推送（队列）”与调试记录见：`模块文档/记忆排期推送.md`。

### 1) 基础间隔（base interval）

- Topic：优先级越高越频繁（约 `14d → 2d`）
- Extract：优先级越高越频繁（约 `7d → 1d`）

实现：`src/srs/incrementalReadingScheduler.ts`

### 2) 到期时间（due）

- 普通路径：`due = baseDate + intentionalIntervalDays + dispersalDays [+ queueDelayDays]`（单位：天）
- **intentional `intervalDays`** 与 **due-only 偏移** 分离：
  - **Phase 0+1（已落地）**：priority-aware 随机分散只进 `due`（`computeDispersalOffsetDays`），**不**写入 `ir.intervalDays`；`computeDispersedIntervalDays` 兼容返回 base
  - 新 Extract 同源同日 sibling `queueDelay` 仍只加在首次 `due` 上，**不得**进入后续 ×1.35 复利
  - 高优先级（≥80）窗口更紧；非高优先新 Topic 前向窗口略放大；SAC 非新卡无普通分散
- 实现：`incrementalReadingDispersal.ts` + `irSchedulingHelpers.computeDispersedSchedule`；写入入口仍经 `saveIRState`
- **Book IR 分散初始化是特殊情况**：各章节首次 `due` 由 `calculateChapterDueDates` 写入；`intervalDays` 仍取优先级对应的基础间隔

### 3) 已读/下一篇后的间隔增长

- Topic：`intervalDays *= 1.25`（上限 60 天）
- Extract：`intervalDays *= 1.35`（上限 30 天）
- **迟到补偿（2026-07-26 落地）**：普通 `markAsRead` 路径（非 SAC）增长基数从「存储的 `ir.intervalDays`」改为「迟到补偿后的 `effectiveBase`」——
  - `elapsedDays`（距上次 `ir.lastRead` 的实际时距，天）为空（新卡首读无 `lastRead`）或 `elapsedDays ≤ storedIntervalDays`（提前/准时读）：`effectiveBase = storedIntervalDays`，行为与旧版完全一致
  - `elapsedDays > storedIntervalDays`（迟到读）：`effectiveBase = storedIntervalDays + (elapsedDays − storedIntervalDays) × IR_LATENESS_WEIGHT`（系数 **0.5**）
  - `effectiveBase` 算出后仍走原有 ×1.25/×1.35 增长、卡种 clamp（60/30 天）、`computeDispersedSchedule`（interval 无随机，due 含 priority-aware offset），不改变后续流程
  - **设计意图**：迟到读完的材料若仍按「存储间隔」增长，很快又会回流形成 backlog 自我强化；部分（而非全额）采信实际时距既能反映「拖久了应适当拉长下次间隔」，0.5 系数又能防止极端拖延（例如放了几个月才读）导致间隔一次性爆炸
  - **不受影响**：SAC（顺序激活章短节奏，见下）、`markAsReadWithPriority`、`updatePriority`、`postpone`（手动/自动/溢出）均维持原逻辑
  - 纯函数：`computeElapsedDaysSinceLastRead` / `computeLatenessEffectiveBase`（`irSchedulingHelpers.ts`）；测试：`irScheduling.lateness.test.ts`
- **例外 — 顺序 Book IR 当前激活章（SAC）**：不按 ×1.25 增长，也不做迟到补偿，而按短节奏重算（priority 0/50/100 ≈ 3/2/1 天，停滞保护上限约 6 天）。详见 [`渐进阅读_BookIR.md`](渐进阅读_BookIR.md) 与 [`记忆排期推送.md`](记忆排期推送.md) §4.5。

### 4) 调整重要性（存储 `ir.priority`）

用户可见术语：**重要性**（UI 不用「优先级」）。存储与调度仍只用连续值 `ir.priority` 0–100（越大越重要/越频繁）。

- **单一生产路径**：`performPriorityAdjust` 委托 `updatePriority`（`irSchedulingMutations`）；纯 helper `adjustIntervalForPriorityChange(cardType, …)` 含卡种 clamp
- **新卡**（`init`/`migrate`）：基础间隔 + 分散初始化；新 Extract 的 sibling delay 只推 `due`
- **已有卡**：比例修正 `intervalDays`（factor `0.6..1.6`）后 **Extract ≤30 / Topic ≤60**；SAC 激活章仍短节奏重算
- `#card.priority` 仍只经现有 `saveIRState` → `syncCardTagPriority` 同步，不另造写入路径
- **纯函数**：`src/srs/incremental-reading/irImportance.ts`
  - 绝对三档（建书 / 导入 setup）：`tierToPriority` → low=**20** / medium=**50**（默认）/ high=**80**；选项文案 `importanceSetupOptions()`（「想读，但不急」/「正常阅读」/「近期要啃完 / 很重要」）
  - 阅读中相对微调：`applyImportanceNudge` — down −15 / up +15 / reset → `DEFAULT_IR_PRIORITY`（50），再 clamp 0–100
- **会话 UI**（`IRActionBar` + `IRImportanceMenu` + `IRSessionShell`）：
  - 主栏「重要性」打开次级菜单：没那么重要了（−15）、更重要了（+15）、设回「正常」（→50）；写入经 `applyImportanceNudge` → `performPriorityAdjust`
  - `Alt+P` 打开重要性菜单（**不是**「更多」）
  - 更多面板**不再**提供绝对低/中/高
- 精确数值仍可在资料库详情抽屉查看；筛选/徽标仍按 `priorityToTier` 归为低/中/高

### 5) 推后（postpone）只移动 due（Batch B2）

- 手动 `postpone`、自动 `applyAutoPostpone`、资料库 `deferIROverflow`：**保留**原 `intervalDays` 与 **`position`**；delay 仅计算新 `due`
- 允许更新：`postponeCount`、`lastAction`、`autoPostponeBatchId`（自动批次）；不增加 `readCount`，不重置 intentional interval，**不**借推后重排 Topic position
- 溢出实现：`irOverflowDefer.ts`（collector 兼容 re-export）

#### 撤销上一篇（会话内单步 undo，2026-07-27）

误点「下一篇」后可立即回到刚才那篇及其阅读位置，而不必等几天后才看到被错误延期的卡。

| 项 | 行为 |
| --- | --- |
| 入口 | ① 会话头部 banner 次级按钮「撤销上一篇」② `Alt+U`（**不**占用宿主 `Cmd/Ctrl+Z`）③ **「下一篇」成功 toast**（`orca.notify` 的 `action`，文案「点此可撤销上一篇」；宿主可能是整卡可点或 action 按钮）。`canUndoNext` 统一判定可用性；toast 过期/失效后再点 → `info`「已无法撤销上一篇…」。toast 会消失，**不**取代顶部按钮与快捷键 |
| 队列 | 被移出的条目按**原下标**回插并切回（`reinsertUndoEntry`）；进度回退一次完成（`unmarkSessionItemCompleted`） |
| 阅读位置 | 用动作前 IR 快照修正队列卡片（`applyIRStateToCard`：`readingBreakpoint` / `resumeBlockId` / 排期 / `isNew`），由既有断点恢复链路对齐 `viewportAnchor`。**不是** `scrollTo` |
| 排期回滚 | `performNext` 返回 `previousState`（`markAsRead` 之前 `loadIRState` 的完整快照）；`undoPerformNext` 用 `saveIRState` **整体写回**，一次覆盖 `intervalDays` / `due` / `readCount` / `lastRead` / `stage` / `lastAction` / 断点 / SAC 计数 |
| 顺序 | 先 flush 当前卡断点（失败只进 banner + `console.error`，**不阻断**撤销）→ **回滚写库** → 成功后才回插队列。反过来会出现「UI 已回去但排期仍被污染」的假撤销；写回失败保留记录以便重试并 `orca.notify("error")` |
| 指标 | `action.next.undo` 从 `completedCount` / `topicProcessed|extractProcessed` 中**减回**，避免会话摘要与今日累计把误点算成阅读 |

边界（有意不做）：

- 仅**最近一次**「下一篇」，单步、无历史栈；离开会话 / 关闭面板 / 队列种子变化即清空
- 当前篇一旦发生**会写库的动作**（再下一篇、推后、完成、跳过、摘录、挖空、问答、方向、重要性、混合复习评分）即失效——撤销只承诺回滚最近一次「下一篇」，不承诺清理其后的写入
- 「下一篇」把队列清空进入完成页后**不提供**撤销（今日统计已结算，回滚成本与收益不匹配）
- 「完成 / 顺序完成本章」**不**做同一套轻量撤销（已有确认框；回滚涉及 strip / plan）

#### 读到文末的「下一篇」确认门闩（2026-07-27）

已读到本篇末尾时再点「下一篇」，先提醒「以后再复习」还是「应点完成移出队列」，避免长期把读完的内容留在队列里。

| 项 | 行为 |
| --- | --- |
| 末区信号 | `resolveEndZoneReason`：`bottom`（`scrollTop + clientHeight >= scrollHeight - 24px`）或 `fits`（全文一屏装下，视为已见末尾）；取真实纵向滚动 owner（同 `resolveVerticalScrollOwner`） |
| 停留门槛 | 进入末区后需停留 ≥ `END_ZONE_DWELL_MS`（4s）才弹；**离开末区（往回滚）即取消并清零计时**。没有该门槛会把短摘录的主路径变成每篇一次确认 |
| 触发面 | 主栏「下一篇」与 `Enter` 共用 `requestNext`；`irSessionNext` 命令广播同样过门闩 |
| 选项 | 「以后再复习」（solid，主推）→ 现有 `handleNext`；「完成，移出队列」（outline）→ 现有 `handleCompleteRequest`（顺序激活章仍进 `IRCompleteChapterDialog`，其余进 `IRArchiveConfirmDialog`，**不绕过**二次确认）；「取消」留在当前卡 |
| 抑制 | 任一分支处理后**会话级**抑制一次性生效，本次会话不再弹（避免反复打断）；新会话重置 |
| 不拦截 | 未读到文末、摘录 / 挖空 / 问答 / 方向 / 重要性、推后（「暂时不读」与「读完离队」不同） |

实现：`irEndOfContentGate.ts`（判定 + 文案，纯逻辑）、`useIRReadingEndZone.ts`（滚动 / ResizeObserver / 切卡后延迟补测，一屏装下时无滚动事件必须靠 RO 兜底）、`IREndOfContentDialog.tsx`。确认类对话框打开期间会话快捷键整体停用，`Enter` 不得穿透触发下一篇。

其他：

- 进度显示为 **已完成 / 本次计划**（`irSessionProgress.ts`），不再使用「当前索引 / 剩余队列长度」
- 收集失败显示「数据读取失败」，不得伪装成「暂无到期内容」（`irCollectResult.ts`）
- 关闭/下一篇/推后/**完成（归档）**前强制 flush 阅读断点；关闭时 flush 失败**不静默关闭**（可重试或强制关闭）
- 打开卡片时恢复：先归零真实滚动 owner → 按 `viewportAnchor.topOffsetPx`（或旧数据：阅读线）**确定性** `scrollTop += delta` 对齐目标块 → 若断点里存有 `selection` 再 `setSelectionFromCursorData`（选区失败只 warn 并继续锚点对齐；捕获侧新写入仅接受非折叠有文本选区，旧数据可能仍带 collapsed selection）→ 几何稳定后释放抑制。对齐抛错必须 `onFailure` 并释放抑制。**不再**使用 `scrollIntoView({ smooth, block: "center" })`
- **断点合并**：`updateReadingBreakpoint` / `mergeBreakpointSave` 在替换 `selection` 或 `resumeBlockId` 且 patch **未**带新 `viewportAnchor` 时**清空**旧 anchor，避免旧偏移对齐新 focus；`ir_record` undo 完整恢复含 anchor
- 恢复以**卡片进入/切换**为生命周期边界：同一 `cardId` + 恢复目标（含 anchor 偏移 / selection offset）只执行一次
- **切卡滚动生命周期**（`irBreakpointRestore` / `useIRReadingBreakpoint`）：进入新卡时**先**将**真实纵向滚动 owner** 的 `scrollTop` 归零，再按有效断点恢复；无断点则保持顶部。**不得**在离开旧卡的 cleanup 中归零（避免旧卡 scroll 监听把断点写成顶部）。切卡时先卸旧 scroll 监听并清 debounce，再启动新卡恢复
- **视图切换归零**（2026-07-27，`viewportScrollReset.ts` / `irSessionViewportReset.ts`）：断点恢复只在**进入阅读卡**时归零，完成页 / 混合复习卡 / 加载失败页没有它接管——结束最后一张长阅读卡后，真实滚动 owner 仍停在原阅读位置，「今日学习完毕」只占一屏，用户必须手动上滚才看得到。现由 `IRSessionShell` 按 `resolveIRSessionViewportResetKey`（阅读条目返回 `null`，其余为 `summary` / `review:<entryKey>` / `load-failed`）在视图 key 变化时调用 `resetViewportScrollTop`，起点为 `scrollContainerRef.current ?? sessionRootRef.current`（内部节点可能被 React 复用而保留 `scrollTop`），再沿祖先链解析 owner。**阅读条目不得在此归零**，否则与恢复对齐互相打架。混合复习分支的 `.ir-reading__scroll` 也挂 `scrollContainerRef`（该分支 `enabled=false`，断点 hook 不会使用它）
- **真实滚动 owner**（`resolveVerticalScrollOwner` in `irBreakpointViewport.ts`）：从本会话 `.ir-reading__scroll` 起沿祖先链解析最近一个 `overflow-y` 为 `auto|scroll|overlay` 且 `scrollHeight > clientHeight` 的节点。运行时常见形态是内部节点随内容撑开（本地无滚动范围），而 host `.orca-block-editor` 祖先才是实际滚动容器——**不硬编码该类名**。断点 scroll 订阅、可见块视口、切卡归零、恢复对齐均针对该 owner；多面板时只沿本会话 DOM 祖先链解析
- **恢复期滚动捕获抑制**（`ScrollCaptureSuppression`）：有效断点恢复进行期间（含几何稳定轮询，默认连续 2 次残差 ≤ 8px 或最多约 1.5s），程序化 reset / 对齐产生的 scroll **不得**触发可见块捕获。抑制在 success / failure / cancel / unmount 时必须释放；不依赖 React effect 声明顺序作为唯一保障。手动 `restore()` 走同一 `startRestore` 路径
- **捕获优先级**：仅**非折叠且含非空文本**的选区优先；折叠 caret **不得**在 flush/下一篇时覆盖当前视口位置。无有效选区时，滚动停止后用 `.orca-block[data-id]` 可见块 + 阅读线估算 `resumeBlockId`，并写入 `viewportAnchor.topOffsetPx`（块顶相对 owner 顶部偏移，可负）
- **交互捕获守卫**（`src/hooks/irBreakpointInteractiveCapture.ts`）：mouseup/keyup 经 `scheduleCapture` 武装 debounce（`INTERACTIVE_CAPTURE_DEBOUNCE_MS = 180`）后 `captureNow`。`captureNow` / `captureFromSelection` / `captureFromVisibleBlock` 三个捕获入口都过 `shouldAllowInteractiveCapture`（闭包 cardId vs `activeCardIdRef.current`，语义与 scroll 路径的 `shouldAllowScrollVisibleCapture` 对齐）：任一为空（会话结束）或不一致（已切卡）时**整体丢弃**本次捕获。另有第二道防线：`cardId` 变化的 effect cleanup 清掉旧卡遗留的交互 debounce。背景：keydown「下一篇」flush 正确断点后，keyup 仍会重新武装携带旧 cardId 闭包的定时器，若切卡在 180ms 内完成，保存通道版本号已更新，不校验就会把**新卡可见块写入旧卡断点**（scroll 路径原有守卫、交互路径此前没有）。回归：`useIRReadingBreakpoint.keyup.test.ts`
- **`ir.breakpoint` schema**：`schemaVersion` 2 增加 `viewportAnchor: { rootBlockId, blockId, topOffsetPx }`；无该字段的 v1 JSON 仍可读；旧仅 `resumeBlockId` 恢复时对齐到**阅读线**（非居中）。进程内保存通道的 `version` 与 `schemaVersion` 无关（且历史编解码会丢弃通道 version）
- **`chapter_browse`**：临时探索态，`allowCapture=false`——不生成新断点；flush 只排空既有保存队列，不按 browse DOM 写回
- 断点保存经单通道队列 + 版本号，旧响应不能覆盖新断点
- **卸载期在途写入排空（2026-07-26，`irBreakpointStorage.ts`，低危#13）**：`BreakpointSaveChannel` 构造时登记到模块级 **WeakRef 注册表**（已卸载组件的通道不被钉住），实例新增 `drain()`（只保证时序，不重复抛已上报的写入错误）；导出 `flushPendingBreakpointSaves()` 在 Orca 数据 API 仍可用时排空所有在途写入，由 `runPluginUnloadSequence` 在复习日志 flush 之后调用（结果字段 `breakpointFlushOk`）。**局限**：只排空已入队的保存——最后一个 debounce 周期内尚未 `captureNow` 的断点仍依赖组件 DOM，卸载时会丢（彻底归零需 hook 挂载期注册 flush，暂未做）
- 滚动容器与正文容器分离：`.ir-reading__scroll` 为会话内滚动锚点（CSS 上仍可 `overflow:auto`）；实际监听/归零以 `resolveVerticalScrollOwner` 结果为准。`.ir-reading__body` 仅承载 Orca 正文块查询范围
- 选区交互使用 Orca 原生选区工具栏；摘录与挖空通过 `Alt+X` / `Alt+Z`（可重绑定）或右侧阅读动作栏触发

### 摘录近上下文 / 章节浏览（landed）

会话内阅读上下文由纯状态机 + Shell 接线驱动；**不**再在 `IRReadingPane` 本地维护 `previewBlockId` toggle。

#### 模式

| 模式 | 适用 | 近上下文条 `.ir-reading__context` | 正文 `.ir-reading__body` |
| --- | --- | --- | --- |
| `extract_focus` | Extract 默认；Topic 概念上同态但无近上下文 | 直接父块；`contextOpen` 默认 **false**（刷到摘录不自动展开） | **仅**当前卡（extract / topic） |
| `chapter_browse` | 面包屑点到祖先/章节（非直接父） | **无**（`contextOpen` false） | **单一**祖先/章节块；**不**再另渲 extract 正文 |

#### 用户路径

- **Extract 默认**：近上下文 = 直接父块、**默认收起**（`contextOpen=false`）；需用户点「展开上下文」或面包屑直接父；展开后父块上**只**给当前 extract 的 `.orca-block` 挂 `ir-reading__context-hide-self`（**不是**隐藏全部 children；兄弟仍可见）
- **「展开/收起上下文」**：仅 `extract_focus` 且存在 `nearContextBlockId` 时显示；toggle `contextOpen`
- **面包屑**：点**直接父** → 保持 `extract_focus` 并打开近上下文，**不**进 browse（再点一次父 → `chapter_browse`）；点**更远祖先/章节** → `chapter_browse`（`browseBlockId = target`）；点当前卡 → 清 browse 回 focus 且近上下文仍收起
- **章节浏览**：正文换成祖先 `OrcaBlock`；进入后 `scheduleLocateBlock` 在滚动根内定位当前 extract 并短暂高亮（`ir-reading__locate-highlight`）；异步渲染可 rAF 重试
- **「返回」**（`IRActionBar`）：**仅** `chapter_browse` 时 `showReturn`；`onReturn` → `reduceReturnFromBrowse` 回 `extract_focus`（近上下文默认仍收起）
- **Topic**：无近上下文条；祖先面包屑仍可 `chapter_browse`，「返回」回 topic 正文

- `resolveBreakpointPreviewId`：**仅** `extract_focus` + `contextOpen` 时返回 `nearContextBlockId`
- **永不以 `browseBlockId` 作为**断点 `previewBlockId`（`useIRReadingBreakpoint` 经 `useIRReadingContext.breakpointPreviewId` 接线）

### 完成页与今日累计统计

- 队列读完或成功启动但今日无卡：完成标题 **「今日学习完毕」**（`irSessionSummaryCopy.ts`），**无**旧副标题「本次渐进阅读会话已顺利完成」；保留统计面板
- **`loadFailed` 分支优先**：数据读取失败绝不能伪装成「今日学习完毕」
- 统计按 **Orca repo + pluginName + 本地自然日（`formatLocalDateKey`）** 持久化到 `localStorage`（`irDailyStatsStorage.ts`），**不**写 Orca block 属性；键前缀 `orca-srs:ir-daily-stats:`
- 刷新渐进阅读面板或同日再次打开且无新卡：只 **load** 今日累计，**不**提交全零会话
- 有活动会话进入完成页：effect 内一次性 `session.end` + `commitIRSessionToDailyStats`（稳定 `sessionId` 去重）；禁止在 render 中 `record("session.end")` 导致 React 重渲染重复累计
- 存储失败：`console.error` + 非阻断 `orca.notify("warn")` + 完成页 `storageWarning`；仍可展示当前会话快照
- 次日使用新 `dateKey` 记录；跨 repo 不得混用

**默认快捷键为一次性播种（2026-07-26，`irShortcutsRegistry.ts`，低危#18）**：`Alt+X`/`Alt+Z`/`Alt+R` 三个默认键只在**首次**加载时 assign；播种完成即写 plugin data 标记 `ir.defaultShortcutsSeeded`（`IR_SHORTCUT_DEFAULTS_SEEDED_DATA_KEY`），此后每次启动读到标记直接跳过——**用户主动解绑/改绑的选择永不被插件覆盖**。个别键因被占用而跳过也视为已播种，不再补种；标记读取失败时保守跳过本次播种（无法排除「用户已解绑」）。`unload` **不回收**快捷键：绑定归用户在 Orca 原生快捷键设置自行管理，回收会抹掉用户自定义。历史误绑 Enter/Shift+Enter 到会话命令的清理逻辑保留。回归：`irShortcutsRegistry` 测试（9 用例）。命令广播带当前 `activePanel`，只驱动对应阅读面板。`Alt+Z` 广播还带 `targetBlockId`（`cursor.anchor.blockId`）：仅当与队列当前卡 ID 一致时 Shell 才 `preventDefault` 并接管——当前为 Topic 且仍在 Topic 正文则提示先创建 Extract；当前为 Extract 则先 flush 断点再走 `convertExtractToItem({ strategy: "keep_extract" })`，**不**因成功挖空而离开队列。Topic 下新建 Extract 子块后立刻制卡时 `targetBlockId` 为子块 ID，Shell 不拦截，由 `createClozeFromEditorCommand` 识别 Extract 并同样 `keep_extract`；普通非 Extract 块仍走常规 Cloze 路径。

### 会话服务（`irSessionService.ts`）

- `performNext` / `performPostpone` / `performArchive` / `performPriorityAdjust`（**委托** `updatePriority`，无第二套公式）

#### `completeIRCard` / 完成语义（章节完成 vs 笔记）

`completeIRCard(blockId)`（及顺序推进里对当前章的 strip）：

| 会清理 | 不会删除 |
| --- | --- |
| `#card` 标签 | 块本身、正文、子块、图片、引用 |
| `srs.*` 复习属性 | `epub.*` 等导入溯源（若存在） |
| 全部 `ir.*` 调度/来源属性（**在该章节块上**） | **Extract 块上**已写入的 `ir.sourceTopicId` / `ir.sourceBookId` 等（Extract 未完成则保留） |
| IR 索引条目 | 资料库结构：书下来源树仍可保留「已完成」上下文章节（见下「资料库三级树」） |

产品含义：主栏 **完成** = **退出 IR 调度与卡身份**，不是删除笔记。顺序书 plan 记 `outcomes[id]=completed`；分散书无 per-chapter plan outcome 时，资料库靠 Extract 的 `sourceTopicId` 合成结构节点。

### 原子制卡（`irConversionService.ts`）

- `convertExtractToItem` / `convertExtractToQA` / `convertExtractToDirection`（`IRConversionStrategy = "complete_extract" | "keep_extract"`；`itemType: "cloze" | "qa" | "direction"`）
  - 转化前快照正文、标签类型、原有 `srs.*`、来源属性、进程内 `_repr` 与 IR（`irConversionBlockState`）
  - 失败：恢复正文/标签/`_repr`/原有 SRS 与来源属性；只删除本次新增属性；独立半成品 Item 删除（`safeCleanup` 共用）
  - 成功且 **`keep_extract`**（**会话挖空 / 问答 / 方向 / `createClozeFromEditorCommand` 主路径**）：保留 Extract 全部 IR 调度字段；`stage=extract.item_candidate`、`lastAction=itemize`；`completedExtract: false`；**不**删索引、**不**要求离开会话队列。Cloze 第一次挖空会把 `#card type` 写成 `cloze`；后续挖空凭 **type=cloze + 仍有 `ir.due`** 识别 hybrid（`irHybridExtract`）。Q&A 目标：`type=extracts` 或仍有 live IR 的非 Topic；Direction 同
  - 成功且 `complete_extract`：`deleteIRSchedulingState` + 去索引，保留 #card、SRS 与 `ir.source*`；`completedExtract: true`
  - 函数参数默认值仍为 `complete_extract`；会话路径**显式**传 `keep_extract`
  - 断点在转化前 flush
  - 验证：Cloze 要求 #card + `type=cloze` + `srs.cN.*`；Q&A 要求 #card + `type=basic` + 任意 `srs.*`；Direction 要求 #card + `type=direction` + `srs.forward|backward.*`
  - Q&A 无答案子块：`step: "validate"`，消息含「Q&A 需要答案子块」，不调用 create

### 队列策略与过载

- `selectQueueWithPolicy`（`irQueuePolicy.ts`）：在时间预算与 `dailyLimit`（**单次**队列硬上限，非跨会话日额度）内组纯 IR 阅读队列；成本可用 `irCostCalibration` 停留校准。
  - **Topic 最低曝光（最终约束）**：队列策略路径将设置 `topicQuotaPercent`（0..100，非法值钳制）映射为 `topicMinRatio`（0..1）；默认设置 20% → 0.2。最终队列按长度复核 floor；无法满足时在 `diagnostics` 返回可测 reason（如 `insufficient_topics`），不静默当成功。
  - **新 Extract 上限（最终约束）**：`newExtractMaxRatio`（默认 0.2）按**最终**队列长度 `floor(N * ratio)` 约束，fill / 探索不得绕过；有足够非新候选时可剔除超额。小队列 `floor(N*ratio)=0` 但仅有新 Extract 可选时允许非空，并诊断 `new_extract_cap_unsatisfiable`（如 `sole_candidate`）。
  - **排序老化（2026-07-26 落地，`irQueuePolicyCore.ts`）**：填充、Topic floor 换出、新 Extract cap 换出、探索换出统一改用**加性得分** `value = priority + min(IR_AGING_CAP=25, overdueDays × IR_AGING_RATE=0.5)`（`cardValue`/`sortByValue`/`sortVictimsLowValueFirst`；`overdueDays` 按本地日边界计，due 当日为 0）——取代此前先按 `priority` 数值、再按「是否逾期」布尔、再按 hash 的多级字典序比较。旧比较器下 p=51 的刚到期卡永远排在 p=50 逾期 100 天的卡之前；新公式下 p=50 逾期 50 天（value=75）可胜过刚到期的 p=74，终结低优先级饥饿。`IR_AGING_CAP=25` 保证老化到极限（p=50 逾期 ≥50 天 → value=75）仍不越过 `highPriorityThreshold`（默认 80）的高优先级硬保护线太多。平票仍用当日稳定 `stableUnitRandom(seed, id)`。select（填充/回填）与 constraints（floor/cap 换出）现共用同一套 core 价值定义，不再各自维护第二套排序。
  - **有界探索（2026-07-26 改为真随机采样）**：`explorationRatio > 0` 且队列 ≥ `MIN_EXPLORATION_QUEUE_LENGTH`(4) 时至少尝试 1 个探索槽；候选池 = 全部未入选、非硬保护卡，用**独立 salt**（`EXPLORATION_SEED_SALT = "exploration"`）的当日稳定随机 `explorationUnitRandom` 做**均匀采样**——与价值排序 tie-break 用的 `stableUnitRandom(seed, id)` 走不同随机流，不再让"平票顺序"与"探索顺序"耦合。替换后重算成本，不得破预算（首卡可超预算的既有语义保留）、不得拆 Topic floor、不得破新 Extract cap；无合法替换则保持原队列并诊断 `exploration_no_legal_swap`；成功换入诊断 `exploration_applied`（新增诊断码）。
  - **稳定随机 seed**：`formatLocalDateKey(sessionStartedAt)` 本地日 `YYYY-MM-DD`（不用 UTC `toISOString` 切日）；与 `sessionStartedAt` 同源，避免跨午夜漂移。
  - Topic 配额**不是** IR Topics vs SRS Items 的混排比例（统一队列里两侧按实际数量均匀铺开）。
  - 测试：`irQueuePolicy.aging.test.ts`（新增，老化排序/受害者选择/探索均匀采样）。
- **会话启动只读（Batch B1，装配阶段本身不变）**：`useIRWorkspaceSession.loadReadingQueue` 在创建/打开/刷新/重试时只收集与选择队列，**不**调用 `applyAutoPostpone`、**不**隐式写任何 block property；`useIRWorkspaceSession` 仍不 import 写路径，结构守卫测试保持绿（`assembleSessionReadingQueue.test.ts`）。
  - 主路径 `collectIRCardsDetailed(name, { readOnly: true })`（动态 fallback 同样传给 `collectIRCards`）；focus 的 `get-block` 回退用 `collectAllIRCardsFromBlocks(..., { readOnly: true })`。
  - `IRCollectionOptions.readOnly`：为 true 时跳过 `ensureIRState`（其内部可能 `saveIRState`/`setProperties`）；仍调用 `loadIRState` 从真实块读取，并在**内存中**解析/补默认。**内存 fallback ≠ 已持久化**。

  - `loadIRState` 失败仍计入 `failedCount` / 可见错误，不得返回伪默认成功卡。
  - focus 经 `assembleSessionReadingQueue` 冻结到最终阅读队列首位（即使不在 policy 队列中也会插队），并遵守既有 `dailyLimit` 截断。`orca.state` 未命中时仍可用 `get-block` 解析 focus（state miss ≠ 后端无数据）。
- **会话启动 auto-postpone（2026-07-26 接回主路径）**：`applyAutoPostpone` 现由**用户显式启动 IR 会话**（今日学习 `autoStart` / 资料库「开始阅读」`beginReading` / 启动页 `onStartSession`）触发，是**独立于、先于** `selectQueueWithPolicy` 装配的显式步骤（`runSessionStartAutoPostpone.ts`，在 `IRWorkspaceShell` 中 `await` 完成——新 due 已落盘 + `invalidateIrBlockCache`——才调用只读 `loadReadingQueue`）。**不**落在 B1 只读装配路径 `useIRWorkspaceSession.loadReadingQueue` 内部——`applyAutoPostpone` 的写入 API 只被 `runSessionStartAutoPostpone` 与 `IRWorkspaceShell` 启动流程引用；「B1 会话装配只读」不变式仍成立。**刷新 / 重试**已启动会话**不**重复触发（`onRetryLoad` 路径不调用）。
  - **当日一次守卫**：新模块 `irAutoPostponeGuard.ts`，localStorage 键 `orca-srs:ir-auto-postpone:{repo}:{plugin}:{本地日}`；读取失败保守跳过本次（避免无法确认是否已跑而重复推迟，`orca.notify("warn", …)`）；写入失败可见但不阻断（同日可能重复整理，同样 `orca.notify("warn", …)`）——读/写均不静默。
  - **候选与保护**：仅旧积压（`due` 本地日 < 今天，`isLegacyBacklog`）+ `priority < highPriorityThreshold`（默认 80，高优先级永不自动推迟）；保留 `keepTopN`（默认 `DEFAULT_AUTO_POSTPONE_KEEP_TOP_N = 20`，按 priority 降序、稳定 hash 平票）参与今日队列竞争；只推迟其余候选的 `due`，保留 intentional `intervalDays` 与 `position`（沿用 Batch B2「推后只移 due」语义）。

- **irBlockCache 预热约束**（`preheatIrBlockCache`）：只接受**后端返回的块**（`get-blocks-with-tags` / `get-blocks` / `get-block` 结果）；**禁止**用 `orca.state.blocks` 预热——state 可能是旧快照，预热会把旧值固化进缓存。索引批量路径与 `collectIRCardsFromBlocksDetailed` / `collectAllIRCardsFromBlocks` 两个入口都会先预热在手块，使后续 `ensureIRState` / `loadIRState` 命中缓存、不再对同批块重复 `get-block`；写入后按块 `invalidateIrBlockCache` 语义不变；`clearIrBlockCache` 仅测试边界清理用。回归：`incrementalReadingCollector.preheat.test.ts`
- **候选块有界并发映射**：两收集入口对候选块的处理走 `mapPool`（`COLLECT_CONCURRENCY = 8`，按下标回填、输出顺序与输入一致），`collectAllIRCardsFromBlocks` 不再逐块串行
- Topic、书籍章节、自动 Extract 与手动 Extract 创建后增量入索引；完成或转 Item 后移出索引
- 会话走队列策略装配（`useIRWorkspaceSession`）
- **来源元数据内存继承**（`inheritSourceMeta`，不写 block property）：Extract 缺 `sourceWebUrl` / `sourceBookId` 时，若同批 `sourceMetaById` 中存在 `ir.sourceTopicId` 父 Topic 且父有对应元数据，则把 web（url/siteName）与 book（sourceBookId；title 仅在 Extract 自身 title 为空时）拷到 `IRCard`。父 Topic 不在本批则不继承

### 跨块摘录与来源溯源（`irRichExtract.ts` + `extractUtils.ts`）

- 跨 fragment / 相邻块选区规划；Extract 创建已接入
- **创建顺序（Batch B2 修补）**：`invalidateIrBlockCache`（标签可见）→ 写来源属性 → 再 invalidate → `ensureIRState` → `updatePriority`（避免 ensure 吃到旧 basic 卡种；sibling 扫描依赖 sourceTopicId）
- **创建时写入的来源属性（耐久，landed）**：
  1. `ir.sourceTopicId` = 最近来源 Topic（嵌套正文下的 Extract 也写 Topic id，不是 direct parent 正文块）
  2. 若该 Topic 带 `ir.sourceBookId`（书章节）：同时写 Extract 的 `ir.sourceBookId` / `ir.sourceBookTitle`
  3. 非书籍 Topic：不写 book 字段
- **收集器（legacy 兼容）**：`incrementalReadingCollector` 可读 Extract 自身属性；若 book 字段缺失且父 Topic **仍 live**，可在内存中继承 book meta（与 web meta 继承同类）。**不得**把「仅内存继承」当作创建后的唯一溯源——章节完成后父 Topic 不再进收集结果
- 自动标记（Topic 直接 child）复用同一 helper，写入正确的 `sourceTopicId=parentTopic`（及可用的 book 字段）
- 完整 WYSIWYG 结构传播与「忽略选区 / 删除已读 / 按标题批量拆分」的完整 UI 仍有限（规划函数存在）

**不可动的边界**（改视觉时务必遵守）：

1. **专注阅读必须保持「块宿主」渲染**——面板宿主渲染深层嵌套树会主线程同步死循环冻死 Orca（2026-07-26 已回退，见 `问题经验.md`）。视觉归一**不触碰**宿主挂载、渲染宿主选择、块渲染路径与虚拟化。

3. 正文最大宽度是**用户偏好**（`irReaderWidthStorage`，默认 820px，预设 720/820/960/1080），**不能**改用 `--srs-measure` 覆盖；`--srs-measure` 只用于阅读 chrome 列（启动页 / 元信息 / 横幅）。
4. 动作栏的 `width` / `padding` 与 `irActionBarLayout.ts` 的 `SAFE_PADDING_BY_TIER` 联动，属几何量不属视觉量，不得按栅格「顺手」改。

### 资料库三级树形与时间带

为解决「按到期日期分组」将同一本书的章节与摘录打散的问题，资料库采用 **自底向上聚合与剪枝**（`buildIRSourceTree` / `irSourceTreeBuilder.ts`）：

1. **顶部时间导航带**（`IRTimeNavigationBar`）：`全部 / 逾期 / 今天 / 明天 / 未来 7 天 / 新卡 / 7 天后` 互斥区间 + 计数胶囊
2. **第一级 - 来源**（`IRLibrarySourceItem`）：有 `ir.sourceBookId` 的按书归拢（Extract **自身持久属性**优先；legacy 可含收集时从同批父 Topic **内存继承** book meta）；带 `web.canonicalUrl` / `web.sourceUrl` 的 Web Import Topic 统一归入「网页」来源，其 Extract 通过 `ir.sourceTopicId` 继承该来源（web 与 book 同源继承，见上「收集与索引」）；其他非书籍主题以主题自身为来源；无法识别父级的摘录进「未归入来源」。不根据标题猜测网页来源
3. **第二级 - 章节**（`IRLibraryChapterItem`）：
   - **live Topic**：章节标题行即 Topic 卡，承担到期日、阶段、重要性、选择、详情与开始阅读；展开后**不再重复渲染「主章节 Topic 行」**
   - **已完成 / 无卡上下文节点**（`card: null`）：完成本章或归档后章节不再是 IR 卡，但资料库**仍保留**该书下的结构行（见 §8），徽标 **「已完成」**；章节行 **不可操作**（无开始阅读 / 提前到期 / 不进章节侧多选）；其下 **Extract 仍可操作**
4. **第三级 - Extract**（`IRLibraryRow`）：仅在章节下缩进显示摘录，支持多选、详情与提前阅读；已有来源/章节上下文时不在每条 Extract 重复显示来源名
5. **剪枝与上下文章节**：搜索或时间区段只让命中卡参与计数/渲染/批量选择；若仅后代 Extract 命中，父章节仅作为弱化的结构上下文，显示「N 个匹配摘录」，不暴露未命中 Topic 的排期和操作（`getIRChapterPresentation`：`isContextOnly` / `isNonActionable`）
6. **固定排序**：UI **不**暴露全局排序控件；来源按含逾期 → 含今天 → 最近到期 → 名称；章节按到期/标题/ID（顺序书按 plan 序）。`irLibraryFilters.ts` 内的 `sortBy` 供筛选管线/测试使用，树形视图以 `irSourceTreeBuilder` 固定序为准
7. **顺序解锁书大纲占位**（`mode === "sequential"`）：`useIRWorkspaceLibrary` 在 `collectAllIRCards(name)` 之后调用 `loadSequentialBookTreeContexts(cards, name)`（合并 live `sourceBookId` 与 **同 plugin/repo 顺序书注册表**，再 `loadBookIRPlan` + 可选 manifest）。`buildIRSourceTree(..., { sequentialBooks })` 按 `selectedChapterIds` 注入**无卡占位节点**（`isSequentialPlaceholder`，`sequentialStatus`: `active` | `pending` | `completed` | `skipped`），**不**创建 `#card` / `ir.*`、**不**进入 IR 队列；**零 live 卡**时仍可为已注册顺序书创建 source 组与完整大纲。默认「全部」视图保留完整大纲；时间带/类型/阶段/重要性筛选只保留真实命中卡。占位行无开始阅读/提前到期/选择。`removed` 不进大纲。顺序书章节按 plan 顺序排序。注册表在 sequential `saveBookIRPlan` 登记、`clearBookIRPlan` 注销；确认无 plan 时 prune。**不全库 `get-all-blocks` 扫描**
8. **已完成章节资料库保留（landed）**——结构与队列分离：

| 模式 | 章节上下文如何出现在树中 | 状态文案 |
| --- | --- | --- |
| **顺序** `sequential` | plan `outcomes` + `selectedChapterIds` 占位（含 `completed`）；Extract 经 `ir.sourceTopicId` 挂到对应 `chapterId`（即使 `card: null`） | 「已完成」/「未解锁」/「已跳过」/「在读」 |
| **分散** `distributed`（及无 plan 的书章节） | **无** live Topic 时，由同书下 Extract 的 **`ir.sourceTopicId`** 合成上下文章节节点（`card: null`，非 fallback）；书组靠 Extract 的 `ir.sourceBookId`（或 live 继承）归拢 | 「已完成」（上下文节点，无操作） |
| **真实队列** | **不变**：仍仅 `collectAllIRCards` / 队列 policy；上下文节点与占位**永不**入队 | — |

9. **「未关联章节的摘录」**（`isFallback: true`，标题固定）：**仅当**摘录在**当前来源组内**无法解析出可挂载的父章节时出现——即缺少可用的 `ir.sourceTopicId`，或 `sourceTopicId` 指向的章在该 source 下既无 live Topic、也无顺序 plan 占位、也未由其它路径合成上下文节点。有可解析 `sourceTopicId` 的摘录**必须**挂在对应章节（含已完成上下文）下，**不得**误入此兜底桶。

标题加载：`useIRWorkspaceLibrary` 的 `titleMap` 除 live 卡与顺序 `selectedChapterIds` 外，还批量 `get-blocks` **Extract 的 `sourceTopicId`**（可能已是完成后的普通块），保证已完成章节行显示真实 alias/标题。

筛选工具栏（`IRLibraryToolbar`）：常驻搜索；类型 / 来源（含「网页」与来源书）/ 阶段 / 重要性按需展开；到期状态主要由时间带驱动。网页来源使用「篇」统计 Topic 数，详情与队列可显示 `web.siteName` 及来源 URL。

### 主面板 Wide View、宿主 chrome 与 Hideable 布局

当统一工作区作为 **面板主 block 视图**打开时（`view === "block"` 且 `viewArgs.blockId` 等于当前 IR 虚拟块），`IRWorkspaceShell` 会：

4. **隐藏宿主编辑器 chrome**（CSS class `srs-ir-host-panel-chrome-managed` 挂在最近的 `.orca-block-editor` 上，卸载时移除）：

   - `.orca-block-handle`
   - `.orca-block-editor-query-tabs-container` / `.orca-block-editor-query-views`
   - `.orca-memoizedviews`
   样式：`display: none !important`（见 `ir-workspace.css`）。

**Hideable 布局（与 Wide View 独立，挂载即生效）**：Orca 用 `.orca-hideable` / `.orca-hideable-hidden` 切换面板内非活动视图，但隐藏后仍可能保留 inline `display: flex`，导致子树在 `content-visibility` 下继续参与布局/绘制。`IRWorkspaceShell` 在生命周期中对 `rootRef` 调用 `attachHideableDisplayManager`（实现：`src/srs/hideableDisplayManager.ts`，与 Flashcard Home 面板共用）：

- 挂接到最近 `.orca-panel` 的 `MutationObserver`（`class` 属性 + 子树）
- 隐藏时：保存原 inline `display`，设 `display: none`，并打 `data-srs-hideable-display-managed`
- 恢复可见时：还原保存的 inline `display` 并去掉 managed 标记
- 卸载 cleanup：恢复已修改元素并 `disconnect` observer

不改 block 数据 / properties / 面板创建逻辑；仅 DOM 布局侧修正。

**安全边界（fail-closed）**：仅当 `shouldManageHostEditorChrome(panel, panelId, blockId)` 为 true 时才启用 Wide View 与上述 class。嵌入 Journal、查询结果、引用预览中的 IR 块**不得**改外层宿主 DOM 或面板 wide 状态。两入口均传 `blockId`：`IncrementalReadingSessionRenderer` 与 `IncrementalReadingManagerPanel`。判定实现：`src/srs/registry/panelTreeUtils.ts`。Hideable 管理器本身对任意能找到 `.orca-panel` 祖先的 `rootRef` 生效，与 chrome 边界无关。

#### 固定快照队列（统一推送，2026-07-27 起）

当本次判定为混合时：

1. 会话启动时收集 SRS 复习卡，纳入**当时已到期、未暂停**的条目；**新卡同样纳入**（新/旧张数与 2 旧 : 1 新的顺序由 `buildReviewQueue` + SRS 日额度决定，见 `irMixedDailyBudget.ts`）
2. 阅读队列由 `selectQueueWithPolicy()` 生成，时间预算为 `UNLIMITED_TIME_BUDGET_MINUTES`，只受 IR `dailyLimit` 截断
3. 复习张数 = 今日额度内的到期卡**全部**；**不再**按时间预算截断，也**不再**用 `floor(R * p / (1 - p))` 按阅读条目数反推
   （旧口径在阅读队列很短时会把几乎所有到期卡挤出会话，用户读完 topic/extract 后必须回首页另开 SRS 复习面板）
4. 交错：两侧各自摊到 `[0,1)` 归一化位置后合并（阅读 `i/R`、复习 `(j+1)/(V+1)`，同位置阅读优先）。有阅读条目时**首项必为阅读**；阅读条目数 ≥ 复习数时不出现连续复习；**任何情况下都不丢条目**（复习数 > 阅读数时必然出现连续复习）
5. 阅读队列为空 → 纯复习队列；两侧都为空 → 完成页
6. 会话中新制 Item、会话中才到期的卡**不进入**当前快照。Again/Hard 且 due 落在短期重学窗口（`SHORT_RELEARN_WINDOW_MS`）内时：800ms dwell **只离开当前卡**，经 `pendingDueRequeue` / `irMixedPendingDue` **跟踪**真实 due，到期后才 append（冻结本次会话复习身份、budget=null 不二次耗日额度；stale token 不双入）。真正 append 时 `session.plan_more` + `addSessionPlannedItem` 各 +1，保证 `completed ≤ planned`。`session.end` 仍只向上对账（`max`）。回归：`irMixedPendingDue.test.ts`、`irMetrics.test.ts`
7. mixed 是**固定快照**：父卡评分不会像独立复习会话那样动态展开子卡 / List 后续条目 / 辅助预览（`gradeReviewCard` 默认 `updateListProgression` 只改 due 不塞卡）。需要这些行为时走独立 SRS 入口
8. 队列构成提示由 `buildUnifiedSessionNotice()` 生成（纯阅读 / 纯复习），只陈述本次快照真实数字

复习条目通过 `IRMixedReviewPane` 复用 `SrsCardDemo` 与 `reviewCardGrading.ts`。评分成功后短暂停留（`IR_MIXED_REVIEW_AUTO_ADVANCE_MS`，默认 800ms）并自动前进（文案「继续学习」）；手动与自动前进共用幂等闸门。

#### mixed 复习卡块可用性（2026-07-27）

IR 面板展示的是 `srs.ir-session` 虚拟块，普通记忆卡通常**不在** `orca.state.blocks` 中。独立 SRS 会话靠 `useReviewCardAvailability` 预检并 `writeToState`；mixed 原先直接挂 `SrsCardDemo`，其内部 `get-block` **不写回 state**，导致永久「加载中…」（切下一张又 miss 一次）。

现对齐独立会话三态（`irMixedReviewAvailability` / `IRMixedReviewPane` preflight）：

| 相位 | 行为 |
| --- | --- |
| loading | 「正在加载卡片…」，不挂评分 UI |
| ready | `resolveBlockExistence(..., { writeToState: true })` 成功后才挂 `SrsCardDemo` |
| missing | 后端明确 null → `onMissing` 从队列剔除；**不**记 `action.review` / 不增加 completed·reviewProcessed |
| unknown | throw/timeout/非法返回 → 保留队列 +「重试」；stale 请求不得覆盖新卡 |

`SrsCardDemo` 改为纯渲染器（无自发 get-block / 无 unknown→skip）；state miss 仅被动兜底文案。回归：`irMixedReviewAvailability.test.ts`。

#### mixed 复习卡 UI 聚焦（2026-07-27）

刷到 `kind: "review"` 时收起渐进阅读视觉层，避免绿茶/书卷纸张主题与阅读顶栏干扰记忆练习：

- 会话壳 **不**挂 `data-ir-theme` / 阅读正文宽度变量；`.ir-reading--mixed-review` 用中性 SRS 表面（`--orca-color-bg-0`）
- 工作区根加 `ir-workspace--review-focus`：顶栏改「记忆复习」+ 队列/关闭，隐藏模式切换 / 刷新 / 设置
- 回到阅读条目时自动恢复完整 IR chrome

#### IR 日额度不被复习吃掉

`IRSessionMetrics` 的 `completedCount` 对阅读推进 / 推迟 / 归档与复习一视同仁地 +1，而 IR 跨会话日额度用的正是该值。统一推送后一次会话可能复习几十张，若直接扣减会把当天阅读队列清零。
`irDailyQuotaUsedFromTotals(totals) = max(0, completedCount − reviewProcessed)`（`todayLearning/todayLearningSummary.ts`）为 IR 额度的唯一口径，`requireIRDailyStatsForSession` 与今日摘要共用；复习张数仍由 SRS 自己的 new/review 日额度约束。

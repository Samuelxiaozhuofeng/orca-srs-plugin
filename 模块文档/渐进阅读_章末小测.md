# 渐进阅读 · 章末小测

> **文档同步日期：2026-08-03**
> **状态：landed（P1 学习闭环：首轮分类 / 修复轮 / 动作小结 / 整理薄弱点 / 定向反馈；Custom Panel 专注答题 + 揭晓后扁平意图条；共享生成取消 / live 同步；制卡落点=出处块 + 只剩 Panel 时自动打开原文面板；「原文」跳转优先左侧 srs.ir-session 阅读面板，无阅读面板才开/复用右侧侧栏；生成偏好可在「AI / Firecrawl 服务设置」面板配置）**
> 与日常 SRS `#choice` 选择题卡 / AI 快捷制卡路径**独立**。

## 目的

用户在 **Topic / 章节** 阅读完毕后，根据**本章全文**自动生成一次性单选题，检验理解。
测验为一次性检查：测完可删，**不**进入题库温习，**不**自动进入 FSRS 复习队列（用户可**显式**经意图条 / 整理薄弱点加入复习卡）。
P1 起支持首轮弱项分类 → 修复再答 → 整理薄弱点制卡，仍不把小测题直接变成 `#choice` 卡。

## 用户入口

| 入口 | 行为 |
|------|------|
| 右侧动作栏 **完成** → 完成确认成功后 | Topic：IR 已归档/移出，**会话 UI 暂不切下一篇**；再弹「章末小测」确认 |
| **⋯ 更多 → 章末小测**（仅 Topic） | 直接弹同一确认框（不归档、不 hold） |
| 斜杠 **GOTIT?** | 任意页面：以当前编辑器 `rootBlockId` 为源，页面底部插入小测 |

确认文案见 `CHAPTER_QUIZ_COPY`（`src/srs/incremental-reading/chapterQuiz.ts`）。

用户点 **开始出题** → 在该 Topic/页面 **末尾**插入 `srs.chapter-quiz` 块并开始生成。

**完成后续停留（postCompleteQuizHold）**：

1. `performArchive` 成功且 `leftCard` → 写库移出 IR 队列（正确）
2. **不**立刻 `removeCurrent`，继续显示本章正文，等用户出题/作答
3. 用户选「暂不需要」→ 再 `removeCurrent` 进下一篇
4. 用户选「开始出题」并测完 → 结束态 **继续下一篇**（或动作栏「下一篇」）再推进会话
5. hold 期间「下一篇/完成」只推进 UI，不再 `performNext`（避免对已归档章二次排期）

## 内容范围

- **仅当前 Topic 子树全文**（BFS，有界：深度 / 块数 / 字符）
- **不**发送整本书
- 收集时跳过已存在的章末小测块子树，避免旧测验污染源文本

常量：`CHAPTER_QUIZ_SOURCE_MAX_*`（同文件）。

## 生成偏好（「AI / Firecrawl 服务设置」面板 → 「章末小测」分区）

配置入口：Headbar 插头图标 / 命令 `${pluginName}.openAIServiceSettings` 的「章末小测」Tab。
持久化在 plugin **data** 键 `ai.chapterQuiz`（`src/srs/settings/chapterQuizSettingsSchema.ts`，`get/hydrate/save` 三件套 + 内存缓存；插件 load 时 hydrate）。

| 字段 | 默认 | 说明 |
| --- | --- | --- |
| `questionCount` | `10` | 默认出题数量（钳制区间 3–30：数字越界钳制、非数字/空输入回退默认） |
| `language` | `auto` | 题目语言：`auto` 跟随源文本；`zh`/`en`/`ja` 指定题干/选项/讲解措辞语言 |
| `customPrompt` | `""` | 自定义提示词（≤500 字符），放入 system prompt 分隔区；**不得**覆盖安全/接地/JSON 协议规则 |
| `model` | `""` | 专用模型 id（仅作用于**出题生成**，`modelOverride` 覆盖全局模型）；空 = 用「连接」页全局模型。追问 / 填空改写仍用全局模型 |

生效路径：

- `insertChapterQuizBlock` / `launchChapterQuiz`：未显式传 `questionCount` 时读偏好（`buildInitialQuizRepr` 记录进 repr，之后不再变）；
- `generateChapterQuizQuestions`：未显式传 `questionCount` / `language` / `customPrompt` 时读偏好，组装 `buildQuizSystemPrompt({ language, customPrompt })`；`prefs.model` 经 `modelOverride` 传给 `callChatCompletions`（空串回退全局模型）。
- **消费边界防御**（不依赖设置 schema）：`questionCount` 最终钳制到 3–30、`customPrompt` 截断到 500，覆盖显式传参与旧 repr 场景。
- 显式传参优先于配置（GOTIT? / 更多菜单 / 完成确认框均走配置默认值）。
- 语言语义与快捷制卡一致：指定语言只改**措辞**，事实与关键术语仍忠实于源文本（小测选项由模型合成、无接地校验，故不约束引用原文）。
- 自定义提示词是**受信指令**，但以分隔区包裹并重申「不得覆盖安全 / 接地 / JSON 输出协议」，避免削弱 SOURCE 不可信边界（与闪卡路径 `clipCustomInstruction` 范式一致）。

### 定向反馈字段（新卷）

AI JSON 在保留 `explanation` 的同时可生成（均为可选；解析失败丢弃该字段，不整卷失败）：

| 字段 | 说明 |
|------|------|
| `correctReason` | 为何正确答案正确 |
| `optionExplanations` | 与 `options` **等长**；各干扰项为何错；正确项为 `""` |
| `confusion` | 易混概念 / 区分点 |
| `sourceExcerpt` | 须 grounded 在合法 `sourceBlockId`；**无有效正数 sourceBlockId 或 ID 被 allowed 集拒绝时丢弃**，不得当接地证据展示 |

旧卷仅有 `explanation` 时 UI 回退显示该字段；`resolveQuestionFeedbackDisplay` 统一优先级。

## 测验体验（UX）

### 双界面分工（无双活答题）

| 界面 | 职责 |
|------|------|
| 原文中的 `srs.chapter-quiz` **块** | **紧凑入口**：生成中 / 失败重试 / 待开始·继续（带进度）/ 已完成摘要。**不**展示完整选项、追问、制卡 UI |
| **Custom Panel** `srs.chapter-quiz-panel` | **唯一完整答题 / 修复 / 整理界面**；右栏打开，**左栏保持 `srs.ir-session`** |

`openChapterQuizInSidePanel` 导航：

- `view: CHAPTER_QUIZ_PANEL_VIEW`（`srs.chapter-quiz-panel`）
- `viewArgs: { quizBlockId }`
- 无右栏则 `orca.nav.addTo(host, "right", …)`；已有右栏则 `goTo` 复用
- 打开/复用后派发 `CHAPTER_QUIZ_PANEL_NAV_EVENT`（`panelId` + `quizBlockId`），避免 Custom Panel 不 remount 时仍显示旧测验
- **不** `goTo` 左侧，避免顶掉渐进阅读

Panel 仅接收 `PanelProps`（`panelId` 等），**必须**：

1. 首次从 `resolveQuizBlockIdForPanel(panelId)` 读 `viewArgs.quizBlockId`
2. 监听 `CHAPTER_QUIZ_PANEL_NAV_EVENT` 更新 local `quizBlockId`（`key={quizBlockId}` 重置体验状态）
3. 缺失/非法 id 时显示错误态（不空白、不伪装成功）

### 共享生成与 live 同步（同进程）

| 机制 | 行为 |
|------|------|
| **共享生成** `chapterQuizLive` | 同一 `quizBlockId` 共用 `AbortController` + `generationId`；block/panel 任一取消都能中止在途请求；取消后迟到结果不得写回 quiz 成功态；**卸载某一实例不 abort** 仍由另一实例等待的共享生成 |
| **Live 同步** | `persist` 成功前/广播 `publishQuizLive`；其它 controller 订阅同 blockId 更新本地 repr（**不**新建持久化；后端仍是 `srs.chapterQuiz`）；跳过发布方自身防回环；卸载对称 `unsubscribe` |

### 学习闭环（P1）

#### 1. 首轮（不打断、不穿插修复题）

- 答题前可勾选 **我不确定**（仍须选选项）；正确+不确定 → `uncertain_correct`
- **跳过**：无答案，记入 `skipped`，直接前进（首轮不揭晓答案）
- 点选选项立即锁定揭晓
- 首轮分类**互斥且冻结**（`firstCategories`）：`certain_correct` / `uncertain_correct` / `wrong` / `skipped`
- **弱项** = 后三者并集，保持原题序；**仅首轮完成（`phase === "done"`）时**冻结为 `weakItemIds`（Y）。`phase === "quiz"` 的 partial reload **绝不**提前冻结，以免锁死早期弱项
- 反馈：错题完整展示 verdict 文案/符号、**展示序字母**+正确答案、定向原因；对题默认折叠讲解（`details`，键盘可操作）
- 修复轮选项已打乱时，反馈字母用 `resolveDisplayedOptionIndices` 的展示下标，不用原始 `correctIndex` 字母

#### 2. 修复轮（同一 Custom Panel，不开新面板）

- 结果页 **开始修复 / 继续修复**：对当前未解决弱项各给 **一次** 计分再答
- 修对 → `repaired[id]=true`；修错 → 仍未解决（文案 **本次未修复**，不作「掌握」断言），可开下一轮
- 展示 `已修复 X/Y`（Y=原始弱项数）
- **不改**首轮 `answers` / `uncertainMarks` / `skipped` / `firstCategories`
- 修复选项**重排**：`buildRepairOptionOrder`（确定性 seed）；`repairOptionOrders` 仅存完整合法排列；畸形 order 丢弃后由 `ensureRepairOptionOrder` 确定性重建
- `normalizeChapterQuizRepr` 交叉校验：queue 仅未解决弱项、去重、按原题序；`repairActive` 仅当有效队列非空；`repairIndex` 钳制；答案/揭晓仅保留活跃队列且下标在选项范围内

#### 3. 动作小结（替换正确率 hero）

不宣称「掌握度」。展示：确定答对 / 猜对或不确定 / 答错 / 跳过；已修复 X/Y；已加入复习 N 张卡（`countRecordedCardAdds` 实计 block id）。
推荐与操作：开始/继续修复、整理薄弱点、继续下一篇（若 `sessionContinueNext`）、删除测验。
**不再**保留与修复冲突的只读「回看错题」主路径；制卡仍用显式 `handle*For(question)`。

#### 4. 整理薄弱点（Panel 内子视图）

- `ChapterQuizWeaknessOrganizer`：从小结进入，返回结果退出；**非**第二 custom panel / 嵌套 modal
- 列出全部原始弱项（含已修复），默认**全不勾选**
- 已有 `cardAdds` 不可重复创建同类型；填空须 AI 预览确认
- 批量**顺序**制卡；`reprRef` + `mergeQuestionCardAdds` 防覆盖
- **cardAdds 持久化失败**：`persist` 回滚乐观本地状态（若仍为当前值）；并对**本项**新创建块执行 `core.editor.deleteBlocks` 回滚；失败则可见错误含残留 blockId，**绝不**报成功；先前成功项仍保留在 `cardAdds`，失败行可重试
- 行样式：section 内**分隔列表**，无嵌套卡片边框/背景

#### 5. 键盘与读屏

- 仅 **`PanelProps.active`** 的 Custom Panel 注册 `window` keydown（非活动面板不抢键）
- `1`–`6` 选选项；`Enter` 揭晓后前进；`↑`/`↓` 移焦点；editable / IME / 修饰键 / 追问区不劫持
- 选项 `role=radio` + `aria-checked`；对错用文案/符号
- `aria-live`：进入小结时播报分类汇总（优先于最后一题 verdict）；错题 live 含展示序正确答案

### 专注主路径（Panel）

每次只有一个主任务：

1. **答题前**：标题/进度、题干、选项；可选「我不确定」/「跳过」
2. **答题后**：正确/错误（含展示字母）、定向讲解；**唯一高强调主操作**是「下一题 / 完成本轮」（sticky solid CTA）
3. 揭晓后在反馈与主 CTA 之间出现**扁平意图动作条**（方案 A），**不再**套「深入理解」大折叠

#### 意图动作条（揭晓后）

三个动词入口，默认展开 0 层：

| 入口 | 行为 |
|------|------|
| **加入复习**（split） | 主按钮 = **一键简答卡**；`▾` 展开菜单：简答 / 填空（填空仍预览确认） |
| **问 AI** | 原地展开追问区；助手回复轻量 Markdown（`renderLightMarkdown`） |
| **原文** | 左侧有 `srs.ir-session` 阅读面板时：请求该面板在正文内 scroll+高亮定位出处块（`CHAPTER_QUIZ_LOCATE_EVENT`，**定向**到左侧面板，不新增侧栏、不 `goTo` 改写阅读面板）；**无**阅读面板时才在**侧栏**打开出处 block 视图（`addTo` 相对答题 Panel 向右；复用已打开出处侧栏 / 本会话缓存，避免叠出三块面板）。**识别 IR 面板**：`findIRSessionViewPanelId` 除 live `block._repr.type` 外，兼容 `properties._repr`（`type: srs.ir-session`）与 `ir.isSessionBlock===true`（真机常只有属性、无 live `_repr`）。已识别到阅读面板时**禁止**再降级开出处侧栏（未 claim 只 toast 失败） |

- **对题**默认顺序：加入复习 → 问 AI → 原文（偏捕获）
- **错题**默认顺序：原文 → 问 AI → 加入复习（偏理解）
- 无 `sourceBlockId`：仅禁用「加入复习」并短提示，不隐藏整条工具栏
- 换题 / 错题游标切换：收起意图面板，清空临时追问 UI
- 展开「问 AI」或「加入复习 ▾」菜单后：`scrollIntoView` 把展开区滚入视野，并聚焦追问输入框（避免被 sticky「下一题」挡住、需手滑）
- 视觉层级：意图 chip 为 outline/sunken；**不得**与「下一题」同权 solid

### 完成本轮、修复与制卡

- 动作小结（非正确率 hero）+ 主操作「开始/继续修复 / 整理薄弱点 / 继续下一篇 / 删除测验」
- 辅助 API **显式接收目标 question**（`handle*For(question, …)`），不隐式绑定 `currentIndex`；修复轮 / 整理器同样显式目标
- 追问历史为临时 UI：换题时清空可接受；请求上下文必须是当前题
- 制卡写入 `repr.cardAdds[questionId]`；**不**改变冻结的首轮 `answers` / `firstCategories`
- **`persist` 失败**：回滚到失败前本地 repr（仅当乐观值仍是当前），并 live 广播回滚；不静默保留脏态
- **Custom Panel 制卡**：
  1. 写卡函数 **不**用 `invokeGroup`（Panel 无编辑器事务组）；顺序 `insertBlock` / `insertTag` / SRS；失败删顶层新块；**禁止**抛错后重跑 callback。
  2. 真机证据：`activePanel` 在 `srs.chapter-quiz-panel` 时 `insertBlock` 返回 `undefined` 且不写入；短暂 `switchFocusTo` 同布局左侧可写 ViewPanel 后写入成功。
  3. `runWithChapterQuizEditorContext`（`chapterQuizEditorContext.ts`）：从面板**树**解析 Custom Panel 之前最近的可写 ViewPanel（支持嵌套 Row/Column，拒绝 quiz panel 自身）→ 保存原焦点 → `switchFocusTo` → **有界等待** `activePanel` 到位，并留出 150ms 宿主编辑器稳定窗口后再次确认焦点（超时/漂移均不执行 task）→ 在同一上下文内完成**写卡 + `cardAdds` persist** → `finally` 恢复右侧；恢复失败 `console.error`，不覆盖制卡错误。不导航、不滚动、不改面板内容。
  4. `useChapterQuizController({ writeContextPanelId: panelId })` 由 `ChapterQuizExperience` 传入；块侧入口不传。
  5. **制卡落点 = 当前题 `sourceBlockId`**（与「原文」同一来源）：简答/填空卡作为该原文块的**子 block**（`lastChild`）写入，紧邻出题依据。`requireQuizCardSourceBlockId` 校验缺失/非法 ID；缺失时「加入复习」禁用并提示，`sourceBlockId` 对应块已删除时写卡函数报「父块不存在」，**绝不退回 Topic 猜位置**。
  6. **只剩 Custom Panel 时自动打开原文 Block Panel**：`resolveChapterQuizEditorHostPanelId` 找不到可写 ViewPanel 时，`runWithChapterQuizEditorContext` 使用 `openPanel`（`{ view: "block", viewArgs: { blockId: sourceBlockId } }`）经 `orca.nav.addTo(panelId, "left", …)` 自动打开相邻普通 Block Panel 并导航到出处块 → 有界等待新面板挂载（`waitForPanelInTree`）→ 切焦点 → 写卡 → 恢复右侧；Custom Panel **不被 `goTo` 顶掉**，新面板制卡后**保留**（默认建议）。打开失败 / 挂载超时均显式报错，task 只执行一次。
  7. **cardAdds 持久化失败回滚**：卡块已创建但 `saveChapterQuizRepr` 失败时，在编辑器上下文内 `core.editor.deleteBlocks` 删除新块；回滚失败则 notify+log 含残留 `#blockId`，且**不**把该 id 记入 `cardAdds`（可重试，避免重复幽灵卡）。批量中先前成功项保留。

### 其它

- 默认 **10** 道 **单选**；点选后立即锁定揭晓
- 生成中可 **取消**；失败自动重试最多 **3** 次（外层预算，`callChatCompletions` 传 `maxRetries: 0`）后提示 **重新生成**
- 本轮结束后可 **删除测验**；入队闪卡与测验块解耦
- 完成入口：仅当 `performArchive` 结果 `leftCard === true` 才弹小测
- 布局：Panel 撑满自身可用高度；内容 `max-width` 克制（约 36rem）；适应窄右栏；Wide View 仍由宿主控制

```ts
  topicBlockId: number,
  phase: "generating" | "quiz" | "done" | "error",
  questionCount: number,
  sessionContinueNext?: boolean
}
```

**属性 `srs.chapterQuiz`（JSON / Text 回退）** — 题目、答题进度、入卡记录、首轮分类、修复态等重状态。
禁止把整套 `questions` 塞进 `_repr`。

扩展状态字段（均可选；`normalizeChapterQuizRepr` 校验，畸形丢弃）：

```ts
uncertainMarks?: Record<string, boolean>
skipped?: Record<string, boolean>
firstCategories?: Record<string, ChapterQuizFirstCategory>
weakItemIds?: string[]          // 仅 phase=done 时冻结/保留

repairActive?: boolean          // 仅当有效 repairQueue 非空
repairQueue?: string[]
repairIndex?: number
repairAnswers?: Record<string, number>
repairRevealed?: Record<string, boolean>
repairOptionOrders?: Record<string, number[]>  // 完整合法排列
```

状态写回：`saveChapterQuizRepr` → `setProperties(srs.chapterQuiz)` + 同步 live 轻量 `_repr`；写后保持 `invalidateBlockCache`。
`persist` 失败回滚乐观本地状态并 live 广播回滚（不覆盖更新的 live）。

Custom Panel **复用同一持久化**，不另建平行数据源；live 广播只同步内存 UI。整理薄弱点仅为 UI 子视图。

## 边界与非目标

- **不**生成多选 / 简答题型（首版仅单选）
- **不**把小测题直接变成 `#choice` SRS 卡
- **不**维护跨会话题库 / 随机温习
- 源文本与 AI 输出均按「不可信数据」进 prompt（BEGIN/END 分隔）
- 错误可见：生成/写卡/保存/取消失败均 `console.error` + notify，不静默吞掉
- 原文块与 Custom Panel **不可同时**作为 live 答题 UI（块侧已收敛为入口）

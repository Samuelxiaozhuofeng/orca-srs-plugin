## 2026-08-10：章末小测追问 / 填空改写异步结果串题

### 问题现象

章末小测在追问或「改写成填空」仍生成时切到下一题或进入修复轮，旧请求稍后返回，会把旧回答、填空预览、错误或 loading 回灌到当前题；新题界面因此显示不属于自己的内容或持续「生成中」。

### 确认原因

`useChapterQuizController` 的两类请求没有各自的 `AbortController` 与 request token；换题只清本地临时状态。旧 Promise 的成功、失败和 `finally` 仍可执行 `setFollowUps` / `setFollowUpError` / `setFollowUpBusy` 或 `setClozePreview` / `setLocalError` / `setClozeBusy`，且没有核对请求发起题号。

### 修改路径

- `src/components/incremental-reading/useChapterQuizController.ts`：追问与填空改写分别使用题号 + 单调递增 token + `AbortController`；每次状态提交前同时核对当前 token 与活动题号。
- 切题、修复轮题号变化、live 状态切换、blockId 变化和组件卸载会取消并失效请求；主动取消的 `CANCELLED` / `AbortError` 不显示成业务错误。
- `handleConfirmClozeFor` 原有 `clozePreview.questionId` 校验保持不变。

### 回归测试

- `src/components/incremental-reading/useChapterQuizController.test.ts`：可控旧 Promise 在切题后才 resolve 时，旧追问 answer 与旧填空 preview/error/busy 均不落到新题；返回原题后新请求仍可提交。

## 2026-08-10：摘录阅读中 AI 快捷制卡误报「请选中文本…」

### 问题现象

渐进阅读 **Extract** 界面，光标已在有正文的摘录块上，执行 AI 快捷制卡仍 toast「请选中文本，或把光标放在有内容的块上」。普通笔记界面无此问题。

### 确认原因

摘录根块本身是 `#card type=extracts`。`isExcludedAiSourceBlock` 曾**一律**把带 `#card` 的块当「已有闪卡」排除：

- 无选区退回整块时：`collectBoundedSubtreePlainText` 跳过摘录根 → 源文为空
- 部分选中摘录正文时：`extractSingleBlockText` 同样拒绝 → empty_selection

非摘录界面光标常在**无** `#card` 的子块上，故不易复现。

### 修改路径

- `src/srs/ai/aiQuickPrompt.ts`：`isExcludedAiSourceBlock` 仅排除 `srs.ai.quickResult` 与**纯 SRS** `#card`（`resolveIRCardType == null`）；允许 topic / extracts / hybrid（live `ir.due`）作源文
- 纯 basic/cloze/choice 等无 IR 的闪卡仍跳过

### 回归测试

- `aiQuickCardFlow.test.ts`：extract 无选区可用；纯 basic 仍 null
- `aiQuickInteract.test.ts`：extract 部分选区可用；hybrid cloze+`ir.due` 可用；纯 #card 仍拒

## 2026-08-09：选择题复习泄题真因是选项 `.orca-tags`，不是题面

### 问题现象

复习未作答即可看到正确选项上的 `correct` 标签 chip。

### 确认原因（真机 DOM）

```html
<span class="orca-tags" contenteditable="false">
  <span class="orca-tag" data-name="correct">correct</span>
</span>
```

1. 宿主用 **`data-name`**，不是 `data-tag-name`；`ChoiceOptionRenderer` 旧 CSS 四条 `data-tag-name="correct|Correct|…"` **从未匹配**。
2. 标签在独立 `.orca-tags` 容器，与正文分离；隐藏整个容器即可且符合「选项区不显示任何标签 chip」。
3. 上一轮把题面改成 `BlockTextPreview` 并未解决泄题（改错了地方）；真机证明泄露来自**选项区** live `Block` 上的标签 chip。

### 修改路径

- 未揭晓：`buildChoiceOptionInjectedCss` 隐藏 `.orca-tags`；揭晓后不隐藏
- 题面：维持 `BlockTextPreview` 纯文本。**禁止**裸 `SafeBlockPreview`（会进 `ChoiceCardBlockRenderer.contentJsx` 选项列表）；**也禁止**「临时把 `_repr.type` 改成 `text` 再挂宿主 `Block`、卸载还原」——为局部渲染改全局 state，同块在笔记中同时打开会闪成普通文本块，卸载未执行时 `_repr` 残留错误值。该方案已实现并**评估后否决回退**，勿再提交。题干富文本须靠只读自绘 content fragments 单独立项。
- 洗牌冻结（`resolveFrozenShuffledOptions`）保留

### 回归测试

- `ChoiceOptionRenderer.tagHide.test.ts`（注意：正确标记仍可在 DOM，断言的是 CSS 规则而非「DOM 无 correct」）
- `ChoiceCardReviewRenderer.questionFace.test.ts`
- `choiceUtils.shuffleFreeze.test.ts`

## 2026-08-09：通用卡块编辑器保存时压平 Cloze / Direction fragment

### 问题现象

- `srs.cloze-card` / `srs.direction-card` 与普通 `srs.card` 共用 `SrsCardBlockRenderer`；用户点击「编辑题目 → 保存」后，整块 content 被替换为单个纯文本 fragment。
- Cloze 的 `clozeNumber` 与 Direction 的方向 fragment 永久丢失，但 `srs.cN.*` / `srs.forward|backward.*` 属性仍保留，导致变体身份与复习进度脱节。

### 确认原因

- 通用渲染器保存题目时固定构造 `[{ t: "t", v: textValue }]` 并调用 `core.editor.setBlocksContent`，没有先检查实际块内容是否包含结构化 fragment。
- 注册表把 `srs.card`、`srs.cloze-card`、`srs.direction-card` 全部指向该渲染器，因此 `_repr.type` 不能成为编辑安全边界。

### 修改路径

- `src/components/SrsCardBlockRenderer.tsx`：用 `getAllClozeNumbers` / `extractDirectionInfo` 检测实际 `block.content`；结构化卡不渲染题目或答案编辑入口并提示回源块编辑；检测异常时 fail-closed、块内提示并通知错误。
- `src/srs/registry/renderers.ts`：注册时把真实 `pluginName` 注入通用渲染器，Direction 检测不猜 fragment 前缀。
- 普通 Basic 的 `setBlocksContent`、缓存失效与 `_repr` 更新链路保持不变。

### 回归测试

- `src/components/SrsCardBlockRenderer.structuredGuard.test.ts`：Cloze / Direction 块均无编辑入口且提示回源块；Basic 仍能编辑并调用 `setBlocksContent`；结构检测抛错时保持关闭并发送可见通知。

### 验证边界

- 自动化覆盖组件输出与保存命令；仍需 Orca 实例目测结构化卡提示的实际布局与主题表现。

## 2026-03-22：顺序书 Extract「完成」被误判为非激活章

### 问题现象

顺序书章节内创建 Extract 后，阅读会话点「完成」报错：`章节 #… 不是顺序书 #… 的当前激活章（active=#…）`，摘录无法普通归档。

### 修改路径

- `irSessionService.tryAdvanceSequentialBook`：`extracts` 或存在 `ir.sourceTopicId` → `not_applicable` → `completeIRCard`
- `isSequentialActiveChapter` / `loadSequentialSessionMeta`：同样排除 extract provenance，避免 SAC/完成本章对话框误判

### 回归测试

## 2026-07-27：Basic 复习「显示答案」后题面 inline 渲染丢失（字体样式/页面引用/标签消失）

### 问题现象

- 复习问答卡（Basic）点「显示答案」后，题面原有的宿主 inline 渲染（字体样式、页面引用、标签 chips 等）全部消失，只剩纯文本；题面容器 `srs-card-front srs-review-face srs-review-face--question` 内文本无格式

- `review-card/EmbeddedReviewBlocks.tsx` `EmbeddedAnswerBlock`：不再挂卡根 `Block` 整树；经 `useSnapshot(orca.state)` 读卡根 `children`，**逐个渲染子块 live `Block`**（`blockLevel=1`、`indentLevel=1`、`initiallyCollapsed={false}`）——子块 `blockId` 与卡根不同，无双实例，子块 inline 渲染保留
- `review-card/BasicCardReviewRenderer.tsx`：删除静态 `front` 分支，题目区显示答案前后**始终** `EmbeddedQuestionBlock`
- `styles/srs-review.css`：删除 `.srs-answer-block > .orca-block > …` 隐藏根 main/handle 规则与 `margin-left: -25.6px` 补偿（答案区不再渲染卡根整树）

## 2026-07-27：EPUB 导入把「第一章」拆成小节、章首正文丢失

### 问题现象

- 阅读器目录有「第一章 信息是什么？」及下属小节；导入后章节列表只有「真相究竟是什么？」等小节，正文章名消失
- 章首 h1 与引言不在任一导入章中（从第一个 fragment 起切）
- 例：Calibre 生成的《智人之上》EPUB2+NCX

### 确认原因

- `expandLogicalFragmentChapters` 对同 spine 文件 ≥2 个 TOC fragment **一律展开**，并**丢弃**无 fragment 的父 TOC 项
- 设计假设是「一文件多并列章」；本书是「一章一文件 + 嵌套 h3 小节锚点」
- TOC 采集曾扁平化，无法用父子关系区分两种结构

### 修改路径

- `epubChapterPlan.ts`：`auto` 整章容器判定 + 实质前缀兜底；`toc-fragments` 保历史
- `epubParser.ts`：层级 TOC（nav/NCX）；默认 `auto`；前缀切片
- manifest `chapterPlan`；旧书 resume → `toc-fragments`

### 回归测试

- `buildEpubChapterWithSubsections` / `buildEpubPrefixPlusFragments`（`epubParser.test.ts`）
- 真书对照：auto ≈21 章含「第一章…」；`toc-fragments` =101 且无章名

## 2026-07-27：视图整体替换后滚动位置不回顶（完成页停在最后一张卡的阅读位置）

### 问题现象

- 刷完最后一张阅读卡，「今日学习完毕」完成页渲染出来了，但界面仍停在上一张长卡片的滚动位置，用户必须手动向上滚才能看到完成页
- 同类：IR 混合会话从长阅读卡切到复习卡、SRS 复习长卡片评分后切下一张 / 进完成摘要

## 2026-07-13：子卡展开遇循环引用误报（自身反链）

### 问题现象

### 根因

- Orca 卡片块可能存在**自身反链**（`BlockRef` 的 `from === to === parentBlockId`，例如 type=3）。

### 解决方案

- 反链图中的自环是合法数据，不等于用户配置的子卡层级。
- 循环保护层无法区分「自环误入」与「真循环」；应在收集层过滤自环。

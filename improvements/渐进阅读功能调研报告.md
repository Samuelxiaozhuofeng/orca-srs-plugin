# 渐进阅读功能调研报告

> 调研日期：2026-08-10
> 调研范围：当前仓库的渐进阅读、Book IR、网页/EPUB 导入、章末小测与相关会话 UI；SuperMemo、RemNote、Readwise 的公开资料；间隔练习与主动提取的代表性研究。
> 性质：产品与代码调研，不实施功能。

## 执行摘要

好的，这份报告的直接结论是：**当前项目不缺“大功能”，最值得投入的是先补可信性边界，再降低摘录与制卡摩擦。**

简单来说，现有系统已经覆盖了渐进阅读的主链路：

`导入/建 Topic → 断点阅读 → Extract → Cloze/Q&A/Direction → 混合复习 → 完成/归档`

它更像一张已经配齐工具的阅读桌。下一步不该继续往桌上堆设备，而应先修好三个会卡住手的抽屉：完成后的写入边界、摘录创建的原子性、部分读取失败的可见性。

建议只按以下顺序推进：

1. **P0：先修 3 个可信性问题**：完成 Topic 后禁止任何 IR 写回；摘录创建失败不留半成品；部分读取失败必须可见。
2. **P1：再修 3 个高频语义问题**：现在读不偷改 due；自动整理尊重用户点名内容且不降低重要性；快速关闭也保存最后阅读位置。
3. **P1/P2：最后做少量增强**：同块摘录保留常用富文本、Q&A 转化前可编辑确认、无需 Firecrawl 的轻量粘贴导入。

本轮不建议增加 PDF 阅读器、RSS 自动摄入、复杂调度器、批量 AI 制卡、知识图谱、完整撤销历史或更多统计仪表盘。

## 1. 当前能力基线

当前实现已经明显超过“试验版渐进阅读”，许多常见建议其实已经落地，不应重复建设。

| 能力 | 当前状态 | 判断 |
| --- | --- | --- |
| Topic → Extract → Item | 已支持 Extract、Cloze、Q&A、Direction，Item 保留来源字段 | 主链路完整 |
| 阅读调度 | 已有重要性、间隔、逾期老化、探索采样、每日上限、自动/手动推后 | 不需要再造调度器 |
| 阅读位置 | 已有选区、可见块、视口偏移、恢复抑制与版本化保存 | 只缺关闭边界补强 |
| 会话 | 阅读卡与记忆卡可统一混排；范围冻结；支持中断、继续和单步“撤销上一篇” | 不需要牌组/队列系统 |
| 负载治理 | 已有积压整理、Topic floor、新 Extract 上限和溢出提示 | 应修语义，不加更多阈值 |
| 来源与上下文 | Extract 保留父块关系、`sourceTopicId`、近上下文和章节回看 | 基础追溯已存在 |
| 输入 | 已有 EPUB 与 Firecrawl 网页导入、正文清洗、去重和回滚 | 缺低门槛粘贴入口 |
| 辅助学习 | 已有 AI 解释、章末小测、薄弱点制卡 | 不宜再堆 AI 入口 |
| 结束语义 | 已有下一篇、推后、完成/归档、顺序书进度 | 需要收紧完成后的只读边界 |

与 SuperMemo 给出的渐进阅读最小能力相比，本项目已覆盖间隔呈现、摘录、挖空、阅读断点、优先队列、自动推后和网页导入等大部分核心项；最明显的产品差距不是算法，而是**富文本摘录保真与入口摩擦**。[SuperMemo 最小定义](https://supermemo.guru/wiki/Minimum_definition_of_incremental_reading)

## 2. P0：先修可信性边界

### 2.1 完成 Topic 后必须进入真正的只读/离队状态

**现状**

- Topic 完成后，`IRSessionShell.tsx:794-808` 为自动询问章末小测而保留当前卡。
- 此时断点仍在 `IRSessionShell.tsx:354-365` 启用，部分排期动作与快捷键也仍可触达；快捷键禁用条件 `IRSessionShell.tsx:1124-1132` 没有覆盖章末小测确认层。
- `irSchedulingMutations.ts:392-435` 会先加载 IR 状态再整包保存。若完成已经剥离 `ir.*`，后续断点或排期写入存在用默认状态重新生成字段的风险。

**最小方案**

- 首选：完成成功后立即让 Topic 离开当前队列；“章末小测”保留在完成前的“更多”入口，不再自动 hold 已完成卡。
- 若必须保留自动询问，则 hold 状态只能显示“开始小测 / 继续下一篇”，同时关闭断点捕获、文末门闩、排期动作和全部会话快捷键。
- 增加一条回归：完成 Topic 后，无论滚动、按快捷键、关闭弹窗还是切换视图，都不得重新写入任何 `ir.*`。

**为什么是 P0**

这是数据语义边界，不是视觉瑕疵。已完成内容被重新加入 IR 会直接破坏用户对“完成”的信任。

### 2.2 Extract 创建需要轻量事务/补偿

**现状**

`extractUtils.ts:336-420` 的顺序是：高亮原文、插入子块、写 `#card`、初始化 IR。标签或 IR 初始化失败时函数直接返回，已经创建的子块和高亮没有统一回滚，可能留下普通子块或半成品卡。

**最小方案**

- 复用现有 Item 转化的“快照 → 创建 → 验证 → 失败补偿”思路，不新建通用事务框架。
- 只跟踪本次动作产生的高亮和新块 ID；后续失败时反向清理。
- 清理失败必须显示残留 blockId，便于用户手动处理；不能用“创建失败”掩盖残留。
- 本轮只保证失败补偿，不扩展成多步撤销历史。

**验收**

- 标签失败、IR 初始化失败各有确定性测试。
- 失败后不存在带正文但无合法卡状态的新 Extract；若宿主清理失败，错误通知包含残留 ID。

### 2.3 部分读取失败要非阻断地展示

**现状**

- `irCollectResult.ts:20-26` 已正确生成 `partial` 状态和失败数量。
- `workspace/useIRWorkspaceSession.ts:265-275` 也保存了该结果。
- 但 `workspace/IRReadingView.tsx:154-170` 只把 `error` 传成失败视图，`IRSessionShell.tsx:1201-1215` 只渲染全量失败；用户会以为队列完整。

**最小方案**

会话顶部显示一条非阻断提示：“有 N 条内容读取失败，本次先继续可用内容”，附一个“重新加载”动作。不要增加错误中心、逐条失败列表或复杂恢复流程。

## 3. P1：尊重用户意图，减少隐性副作用

### 3.1 “现在读”只聚焦，不修改到期日

资料库已经同时提供“现在读”和“改到今天”（`workspace/IRLibraryRow.tsx:97-117`），但未来卡点击“现在读”仍会在 `workspace/IRWorkspaceShell.tsx:416-422` 判定为需要提前，再由 `workspace/useIRWorkspaceSession.ts:321-337` 写 `due=今天`。

用户临时打开后退出，也会留下今天的到期债务。这让两个按钮的文案承诺失去区别。

**建议**

- “现在读”：只设置本次冻结会话的 focus，不改长期排期。
- “改到今天”：继续作为显式的 due 写入动作。
- 用户真正完成/下一篇后，再按现有规则重排。

### 3.2 自动整理必须保护点名卡，并停止自动降重要性

**现状**

- `workspace/runSessionStartAutoPostpone.ts:94-102` 调用自动推后时固定传入空 `protectedIds`。
- 资料库点名某卡后，`workspace/IRWorkspaceShell.tsx:293-300` 先做全局自动整理，再装配 focus；点名卡有机会先被推走。
- `irOverloadService.ts:229-249` 在反复自动推后时还会降低 priority，把“今天容量不足”解释成“内容不重要”。

**最小方案**

- 明确点名的 cardId 必须加入 `protectedIds`。
- 自动整理只移动 `due`，不修改重要性。
- 不增加新的算法参数；如需用户控制，只保留一个“开始学习时自动整理旧积压”的总开关。

### 3.3 快速关闭也要捕获最后一个断点

应用内关闭会显式调用 `breakpoint.flush()`（`IRSessionShell.tsx:1100-1112`），但 React 直接卸载时，`useIRReadingBreakpoint.ts:472-486` 只清理 debounce。全局卸载只能排空已入队写入，`irBreakpointStorage.ts:87-95` 已注明仍在 debounce、尚未 capture 的最后位置无法代存。

**最小方案**

- 先在 Orca 实机复现“滚动后立刻用宿主 X 关闭”。
- 若确认存在，在 panel-close 或 hook 卸载前同步 capture 一次，并把产生的 promise 纳入现有 `BreakpointSaveChannel`。
- 仍只保存一个可信断点，不引入“最后浏览位置 + 最远阅读位置”的双进度模型，也不扩展跨设备同步。

### 3.4 顺序书暂停后提供一个恢复入口

批量移出当前章会把顺序计划设为暂停（`bookIRRemovalService.ts:95-103`）；仓库已有 reconcile/retry 服务，但资料库书籍行目前只有全选和整本移出（`workspace/IRLibrarySourceItem.tsx:111-130`），占位章节也不可操作。

**建议**

仅当 `activeChapterId=null` 或计划有 `lastError` 时，在书籍来源行显示“继续顺序阅读 / 修复”，直接复用现有 reconcile。不要新建计划管理页。

## 4. P1/P2：值得增加的轻量功能

### 4.1 同块 Extract 保留常用行内格式

**价值**

来源保真是成熟阅读工具的共同重点。RemNote 允许笔记引用精确回跳原文，Readwise 也保留高亮与原文位置；SuperMemo 的最小定义明确包含富文本与引用传播。[RemNote Reader](https://help.remnote.com/en/articles/6690975-learning-from-pdfs-and-files-with-the-remnote-reader) · [Readwise 高亮与回跳](https://docs.readwise.io/reader/docs/faqs/highlights-tags-notes)

**当前缺口**

`irRichExtract.ts:87-151` 只拼接 `fragment.v`，`extractUtils.ts:345-354` 最终固定写成单个纯文本 fragment。跨 fragment/跨块的选区路径已经存在，缺的是格式保留，不需要重写选区系统。

**第一版边界**

- 只处理同块选区。
- 只保留 Orca 已验证可往返的加粗、斜体、链接和高亮等行内 fragment。
- 跨块仍按纯文本加换行；图片、表格、文件和复杂引用后置。
- 遇到不支持格式时允许降级为文字，但应明确提示“部分格式已简化”。

### 4.2 Q&A 转化前给一个双字段确认

当前入口位于“更多”，并约定“Extract 正文=问题、首个子块=答案”（`IRSessionMorePanel.tsx:90-103`）。规则虽可用，但用户点击前很难确认最终卡面。

**建议**

打开一个紧凑的“问题 / 答案”双字段确认层，预填现有正文和首个子块，允许编辑后继续复用既有原子转化服务。不要做模板系统、批量 AI 制卡或卡型向导。

### 4.3 增加无需 API Key 的轻量粘贴导入

网页导入当前依赖 Firecrawl，入口也明确要求 API Key。成熟产品共同支持低摩擦保存；SuperMemo 的入门流程甚至直接以“复制粘贴文章”作为起点。[SuperMemo 入门流程](https://supermemo.guru/wiki/Incremental_reading_step_by_step)

**最小版本**

- 一个文本区：粘贴正文，填写标题，可选来源 URL。
- 复用现有 Topic 初始化、来源字段和写入回滚。
- 第一版只保证纯文本；确认真实需求后再复用现有 HTML 清洗/outline 管线。
- 不做浏览器扩展、RSS、批量导入、后台自动抓取。

这项应排在可信性修复之后。它提升新用户可达性，但不比数据边界更优先。

## 6. 用户实际会感受到什么

- 你说“**现在只想读这篇**”，插件会临时聚焦它，而不是悄悄把它改成今天到期。
- 你说“**把这段做成问答**”，插件会先让你看清问题和答案，再落成卡片。
- 你刚滚到文章下半段就关闭面板，插件会尽量保存最后位置，而不是下次跳回旧断点。
- 某几条内容读取失败时，插件会明确告诉你数量，同时让其余内容继续学习。
- 摘录创建中途失败时，要么完整成功，要么清理干净；清不掉时会告诉你残留在哪里。

## 7. 为什么这条路线更值

- **保护已有数据**：先消除半成品和完成状态复活，再谈新增能力。
- **减少隐性副作用**：按钮含义与实际写入一致，用户更敢使用自动整理。
- **复用现有模块**：绝大多数建议沿用现有队列、事务、导入和恢复逻辑。
- **容易验证**：每项都能用窄测试和 Orca 中的单一操作场景验收。
- **控制复杂度**：不引入新调度器、新知识模型或新的长期状态中心。

## 8. 明确暂不做

以下方向目前收益证据不足、宿主集成成本高，或会把产品带向另一套系统：

- 完整 PDF 阅读器、OCR、视频/音频渐进学习。
- RSS、邮件、浏览器扩展和大批量自动摄入。
- 更复杂的 ML 排期、可编辑算法公式和大量调度参数。
- 整篇 AI 总结、默认批量 AI 制卡、AI 自动判断重要性。
- Deck/preset/filter 查询语言、队列拖拽和多套持久队列。
- 自动知识图谱、概念本体和语义传播系统。
- 多步 undo 历史中心、复杂统计、预测负载图和游戏化。
- 重新引入 10/20/30 分钟时间盒。
- 强制频繁随机换文。阅读中断研究提示，打断可能损害跨段整合；这不是对渐进阅读的直接否定，但足以支持“让用户自己选择何时换篇”。[Foroughi 等，2015](https://pubmed.ncbi.nlm.nih.gov/25867225/)

## 9. 建议落地顺序

### 批次 A：可信性修复

1. 完成 Topic 后零 IR 写入。
2. Extract 创建失败补偿。
3. `partial` 收集结果可见。

完成这三项后再做 Orca 实机回归，不夹带 UI 重做。

### 批次 B：主路径语义

1. “现在读”与“改到今天”彻底分离。
2. 自动整理保护 focus，且不改重要性。
3. 验证并修补宿主关闭前最后断点。
4. 顺序书异常时暴露现有修复入口。

### 批次 C：最多选择一项新增功能

优先顺序建议为：

1. 同块富文本摘录保真。
2. Q&A 双字段确认。
3. 纯文本粘贴导入。

一次只做一项，根据真实使用反馈决定下一项，不并行扩展格式、AI 和新调度逻辑。

## 10. 研究证据与边界

学习科学能支持的是“主动提取”和“间隔练习”，不能直接证明任何一套完整渐进阅读产品流程最优：

- 检索练习对长期保持有稳定收益。[Roediger & Karpicke，2006](https://doi.org/10.1111/j.1467-9280.2006.01693.x)
- 主动提取在代表性实验中优于额外学习或概念图活动。[Karpicke & Blunt，2011](https://pubmed.ncbi.nlm.nih.gov/21252317/)
- 大型综述将练习测试与分散练习评为高效策略，而重读与单纯高亮的普适收益较低。[Dunlosky 等，2013](https://www.psychologicalscience.org/publications/journals/pspi/learning-techniques.html)

本轮没有找到对“完整 SuperMemo 式渐进阅读工作流”的同行评审对照研究。因此，优先队列、交错阅读、自动推后等应被视为**合理产品机制**，而不是“科学证明的最优流程”。报告也没有把 SuperMemo 关于大规模随机交错与创造力的产品主张当作实施依据。

- 阅读了 `模块文档/渐进阅读.md`、Book IR、章末小测、网页/EPUB 导入及两份既有优化规划。
- 对摘录创建、断点、阶段漏斗、会话完成、自动推后、资料库入口、网页 URL 与导入路径做了静态代码核对。
- 相关现有回归测试执行结果：7 个文件、63 项测试全部通过。命令覆盖断点生命周期、keyup 交互、断点存储、自动推后启动、归档、文末门闩和快捷键。
- 本报告未修改业务代码，也未进行 Orca 宿主内手工验证。涉及宿主关闭、弹层事件穿透和完成后写回的 P0 项，应在实施前先做最小实机复现。

一句话收尾：**先把“完成、摘录、断点”三处主链路拧紧，再决定要不要添新工具。**
